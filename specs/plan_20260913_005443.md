# Execution Plan: Enterprise Dynamic Pricing System

An Enterprise Dynamic Pricing System powered by Next.js (App Router), Supabase (PostgreSQL & Realtime state persistence), and Google GenAI Interactions API (`@google/genai` SDK v2.3.0+) utilizing `gemini-3.7-flash`. The system models pricing as a Markov Decision Process (MDP) with a Deep Reinforcement Learning (DRL) reward function, enforced by Policy-as-Code safety guardrails and visualized via a commercialization dashboard with EBITDA lift tracking.

---

## 1. Summary of Analysis

The specification file (`specs/info.md`) defines a 5-phase enterprise dynamic pricing architecture:

1. **Foundational Data Architecture ($S_t$)**: PostgreSQL schema capturing product master data, inventory levels, competitor price feeds, contractual guardrails, pricing decision audit logs, and sales events.
2. **Next.js API & GenAI SDK Setup**: Integration of `@google/genai` using `gemini-3.7-flash` and `GoogleGenAI` client for interaction-based stateful orchestration.
3. **Multi-Agent System (MAS)**: Managed specialized worker agents (ERP Inventory Agent, Trade Promotion Agent, Dynamic Pricing DRL Agent) with function calling tools querying Supabase.
4. **Policy-as-Code Guardrails**: Dual-layer interceptor combining deterministic math limits ($\pm 15\%$) and semantic safety checks via `gemini-3.7-flash` for anti-gouging protection, logged to Supabase.
5. **Commercialization Dashboard**: Next.js App Router UI with React Server Components for EBITDA lift & performance fee tracking (15–25%), Supabase Realtime streaming for live $S_t$ updates, and an Explainable AI (XAI) reasoning panel.

---

## 2. Key Requirements Identified

- **Ecosystem / Stack**: Next.js (App Router), TypeScript, Supabase (PostgreSQL & Realtime), `@google/genai` (SDK v2.3.0+).
- **Core Model**: `gemini-3.7-flash` for low-latency reasoning and agent interaction.
- **SDK Pattern Rules**:
  - `import { GoogleGenAI } from '@google/genai'`
  - `const ai = new GoogleGenAI({ apiKey: ... })`
  - `ai.interactions.create({ agent, input, store: true })`
  - No legacy `google-generativeai` imports or `GenerativeModel` classes.
- **Safety & Compliance**: Deterministic hard limits + semantic LLM anti-gouging checks before database updates.
- **Outcome-Based Commercialization**: Value-based pricing calculation (15–25% of net EBITDA lift).

## 4. Step-by-Step Implementation Flow

### Step 1: Database Schema & Supabase Configuration (`db-schema`)
- Define SQL schema in `supabase/migrations/20260401000000_schema.sql`.
- Create tables with foreign key relationships, `uuid-ossp` extensions, and performance indexes on `(product_id, created_at DESC)` and `(product_id, timestamp DESC)`.
- Create view `ebitda_lift_summary` to aggregate 30-day gross profit lift.
- Create TypeScript types matching the database schema in `lib/db/types.ts`.

### Step 2: Next.js API & GenAI SDK Setup (`backend-api-setup`)
- Configure `lib/genai.ts` exporting `GoogleGenAI` client initialized with `GOOGLE_GENAI_API_KEY`.
- Build `lib/agents/orchestrator.ts` defining `pricing-orchestrator-v1` with `gemini-3.7-flash` and system instructions for MDP state routing.
- Create Next.js API Route `app/api/pricing/evaluate/route.ts` taking state vectors and calling `client.interactions.create` with `store: true`.

### Step 3: Multi-Agent System Implementation (`mas-implementation`)
- Develop tools in `lib/agents/tools.ts`: `get_inventory_status`, `get_map_constraints`, `get_market_data` querying Supabase tables.
- Define worker agents in `lib/agents/definitions.ts`:
  - **ERP Inventory Agent**: Analyzes stock levels & lead times.
  - **Trade Promotion Agent**: Enforces Minimum Advertised Price (MAP) rules.
  - **Dynamic Pricing Agent**: Evaluates DRL Reward Function $R_t = \alpha \cdot \text{Margin} + (1-\alpha) \cdot \text{Volume} - \beta \cdot \text{Churn}$.
- Implement orchestration flow in `app/api/price-optimizer/route.ts` chaining agent interactions sequentially.

### Step 4: Policy-as-Code Safety Guardrails (`guardrails-safety`)
- Implement `verifyPricingPolicy` in `lib/pricing/guardrails.ts`:
  - Check hard mathematical bound: delta $\in [-0.15, +0.15]$.
  - Call `gemini-3.7-flash` via structured output JSON for anti-gouging validation.
  - Log audit records to Supabase `pricing_policy_logs`.
- Build API interceptor `app/api/pricing/update/route.ts` returning HTTP 403 on violation or committing price updates on approval.

### Step 5: Commercialization Dashboard Frontend (`frontend-dashboard`)
- Create `components/dashboard/CommercializationMetrics.tsx`: React Server Component computing gross margin lift, MDP policy reward, and value-based fee ($20\%$).
- Create `components/dashboard/StateSpaceMonitor.tsx`: Client component connecting to Supabase Realtime channel `state_space_updates` displaying $S_t$ table with live actions ($A_t$).
- Create `components/dashboard/AgentReasoning.tsx`: Interactive component invoking `gemini-3.7-flash` Interactions API to generate natural language explanations of pricing actions.
- Assemble root layout and main dashboard view in `app/page.tsx`.

## 5. Potential Challenges and Solutions

1. **Sub-second Latency vs Multi-Agent Chaining**:
   - *Challenge*: Calling 3 sequential LLM agents could introduce latency.
   - *Solution*: Use `gemini-3.7-flash` for all agent interactions and parallelize independent tool calls (e.g., fetching inventory status and MAP constraints concurrently).
2. **Deterministic Safety Enforcement**:
   - *Challenge*: LLMs may occasionally recommend prices outside safe business bounds.
   - *Solution*: Hard bounds ($\pm 15\%$) are validated deterministically in TypeScript *before* calling the database update, ensuring agent recommendations never bypass hard business logic.
3. **SDK Migration & API Compliance**:
   - *Challenge*: Using legacy `@google/generative-ai` SDK patterns by mistake.
   - *Solution*: Enforce strict use of `@google/genai` with `GoogleGenAI` instance and `client.interactions.create` / `client.agents.create`.
